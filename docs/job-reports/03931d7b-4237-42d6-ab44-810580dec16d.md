# JPEG OCR case: text mila, financial extraction kyun ruki

**Original job:** `03931d7b-4237-42d6-ab44-810580dec16d` (`needs_review`)

**Fix verify karne wala naya job:** `2970286f-8e8b-43b9-a47b-034ee498a598` (`unsupported`)

**File format:** JPEG. Is report mein identity number, naam aur birth date repeat nahi kiye gaye hain.

## Kya hua tha?

JPEG upload successful tha. Worker ne file verify ki aur Tesseract OCR se ek page ke 11 text blocks read kiye. Kuch blocks ki confidence kam thi, isliye `LOW_OCR_CONFIDENCE` warning aur reader status `PARTIAL` aaya. Phir rule-based classifier ne document ko `unknown` kaha. Financial extraction step tak workflow gaya hi nahi; isliye `result: null` aur `models_used: []` the. Claude ka model config mein selected tha, lekin us job mein Claude ko call nahi kiya gaya.

OCR text mein `PERMANENT ACCOUNT NUMBER`, `FATHER'S NAME` aur `DATE OF BIRTH` jaise identity-document cues the. Pehle classifier sirf literal `PAN card` phrase pehchanta tha. Isi wajah se original job `UNKNOWN_DOCUMENT_TYPE` ke saath `needs_review` bana. File JPEG hone mein koi problem nahi thi.

## Kya fix hua?

Classifier ab PAN card ke full heading ko identity fields ke saath pehchanta hai. Sirf invoice par printed seller PAN number dekh kar invoice ko reject nahi karta. Aise document ka financial job status ab `unsupported` aur code `UNSUPPORTED_DOCUMENT_TYPE` hota hai, kyunki invoice/bill/receipt ka financial schema is par lagu nahi hota.

Saath hi, API mein alag `text_extraction` object add hua. Isme reader quality, combined plain text aur page-wise text milta hai, chahe financial status `unsupported` ya `needs_review` ho. Ye stored CDR se banta hai; original job ko bhi GET karne par plain text milta hai. UI ke Overview mein text dikhta hai aur copy kiya ja sakta hai. OCR/vision correction ke alternative candidates CDR mein alag rehte hain.

## Naye job ka actual verification

| Check | Result |
|---|---|
| JPEG read aur Tesseract OCR | 1 page, OCR action completed |
| Financial classification | `unsupported` |
| Text extraction | `partial`, 1 page, 258 characters |
| AI model actually used | Koi nahi (`models_used: []`) |
| Financial field extraction | Nahi chali (`result: null`) |
| API error message | Document invoice/bill/receipt scope ke bahar hai |

`partial` ka matlab kuch OCR text uncertain hai. Sensitive identity fields ko is raw OCR ke basis par verified maana nahi chahiye. API ka `source_document` har block ka text, source, location aur confidence deta hai, jisse reading inspect ki ja sakti hai.

Browser: `http://localhost:8000/app?job=2970286f-8e8b-43b9-a47b-034ee498a598`

API: `GET /v1/extractions/2970286f-8e8b-43b9-a47b-034ee498a598` mein `text_extraction.text`, `text_extraction.pages`, `source_document`, aur `processing_steps` dekhein. Original job ID par bhi ab `text_extraction` milta hai; uska historical status change nahi hua.
