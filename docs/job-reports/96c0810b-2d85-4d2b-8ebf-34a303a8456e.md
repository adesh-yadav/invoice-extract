## Why `TOTAL_MISMATCH` occurred

The extracted result contains these values:

| Field | Extracted value |
|---|---:|
| Subtotal | ₹15,364.26 |
| Discount total | ₹33.90 |
| Tax total / IGST | ₹2,759.64 |
| Shipping after discount | ₹0.00 |
| Grand total | ₹18,091.00 |

The validator calculates `subtotal - discount_total + tax_total + shipping + other_charges + round_off`. With the extracted values, that is **₹15,364.26 − ₹33.90 + ₹2,759.64 + ₹0.00 = ₹18,090.00**. The PDF prints **₹18,091.00**, so the difference is **₹1.00**. The high-severity issue correctly keeps the job in review even after Claude's repair pass.

The source table shows product net amount **₹15,331.36**, IGST **₹2,759.64**, and total **₹18,091.00**. Its shipping row shows **₹33.90 charge and −₹33.90 discount**, making shipping net zero. Thus `₹15,331.36 + ₹2,759.64 = ₹18,091.00` reconciles to the printed total. If the schema instead represents subtotal **before** the shipping discount, `₹15,365.26 − ₹33.90 + ₹2,759.64 = ₹18,091.00` also reconciles. The extracted ₹15,364.26 matches neither representation. An explicit subtotal of ₹15,364.26 does not appear in the supplied CDR, so it appears to be an unsupported derived value; a reviewer should confirm the intended subtotal convention before changing the stored result.

Relevant source references are table `p1_t1`, amount blocks `p1_b17`–`p1_b19`, and the cited grand-total block `p1_b19`. Seller, invoice number and grand total all have source citations; the only reported validation issue is arithmetic.

## What is stored and returned

- `uploaded_files`: file metadata; original binary is on the persistent upload volume.
- `extraction_jobs`: status, stage, selected extraction model, prompt/schema versions and timestamps.
- `extraction_events`: the 16 ordered processing actions above, including which model roles actually ran.
- `extraction_sources`: full CDR JSON with native text blocks, coordinates and recovered tables. The same CDR is returned as `source_document` and from the `/cdr` endpoint.
- `extraction_results`: extracted financial JSON, evidence and validation report.

This report omits the buyer address, tax identifiers and payment references from the source document. They remain available in the restricted API/DB result for authorized review.
