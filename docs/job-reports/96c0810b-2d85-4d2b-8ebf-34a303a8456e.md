## source_document/CDR ko kaise samjhein

CDR ka matlab Common Document Representation hai: reader ko jo document mein dikhai diya, uska structured record.

- **reader_status = COMPLETE:** PDF ka readable content successfully mila. Ye financial result correct hone ki guarantee nahi hai.
- **methods = pdf_native:** Text PDF se directly nikla. Page ko image bana kar OCR nahi chalaya gaya.
- **35 text_blocks:** Har block ka ID, text, order aur normalized bbox (page par location) store hai.
- **confidence = null:** Native PDF text ke liye Tesseract confidence score hota hi nahi. Iska matlab low confidence ya OCR failure nahi hai.
- **2 tables:** PDF reader ne table structure bhi recover kiya. Main item/totals table p1_t1 hai; payment table p1_t2 hai.
- **warnings = []:** Reader ne is page ke liye technical reading warning nahi di.

Important current code detail: **CDR mein tables store hote hain, lekin LangChain extractor ke prompt mein abhi sirf text_blocks jaate hain; structured table rows alag se nahi jaate.** Amounts kuch text blocks mein multiple columns ke saath flatten ho gaye hain. Ye subtotal galat samajhne ka ek plausible reason hai, lekin Claude ke internal decision ka exact cause response se prove nahi hota.

## ₹1.00 ka TOTAL_MISMATCH exactly kaise bana

Claude ke final result mein ye totals hain:

| Field | Extracted amount |
|---|---:|
| subtotal | ₹15,364.26 |
| discount_total | ₹33.90 |
| tax_total / IGST | ₹2,759.64 |
| shipping | ₹0.00 |
| grand_total | ₹18,091.00 |

Current validator ka formula hai:

    expected = subtotal - discount_total + tax_total + shipping + other_charges + round_off

Is job par:

    ₹15,364.26 - ₹33.90 + ₹2,759.64 + ₹0.00 = ₹18,090.00

PDF mein printed total **₹18,091.00** hai. Difference **₹1.00** hai. Code ₹0.02 se bada mismatch high severity maanta hai; isliye TOTAL_MISMATCH aur needs_review mila. Repair pass ke baad bhi wahi issue aaya.

Source table p1_t1 aur blocks p1_b17–p1_b19 mein product net **₹15,331.36**, IGST **₹2,759.64** aur printed grand total **₹18,091.00** dikhte hain. Shipping row mein charge **₹33.90** aur usi par discount **−₹33.90** hai; shipping net zero hai. Source ke hisaab se ek simple reconciliation:

    ₹15,331.36 + ₹2,759.64 = ₹18,091.00

Agar subtotal ko discount se **pehle** ke gross amount ke roop mein define karein, to doosra mathematically consistent representation hai:

    ₹15,365.26 - ₹33.90 + ₹2,759.64 = ₹18,091.00

Extracted subtotal **₹15,364.26** in dono representations se match nahi karta. Shared CDR mein ₹15,364.26 explicit subtotal ke roop mein nahi dikh raha; isliye yeh model ka unsupported/inaccurate derived value lagta hai. Subtotal ka exact business meaning decide kiye bina automatic correction karna theek nahi hoga.

## needs_review aur error null ek saath kyon hain?

**reader_status COMPLETE** = document ka text readable tha.

**error null** = worker, API aur Claude call mein technical exception nahi aaya.

**validation.passed false** = extracted financial JSON arithmetic check pass nahi kar paya.

**status needs_review** = human review ki zarurat hai; service ne uncertain amount ko silently approve nahi kiya.

Ek repair attempt already ho chuka. Same Claude model ne mismatch resolve nahi kiya; workflow ne second repair loop nahi chalaya.

### Code mein provider ke default model names

| Provider value | Default model |
|---|---|
| anthropic | claude-haiku-4-5-20251001 |
| openai | gpt-4.1-mini |
| google | gemini-2.5-flash |
| ollama | gemma3:4b |

Ye defaults provider_factory.py mein hain. **EXTRACTION_MODEL blank** ho to LLM_PROVIDER ka default model use hota hai. **VISION_PROVIDER blank** ho to extraction provider inherit hota hai; VISION_MODEL bhi blank ho aur provider same ho to extraction model reuse hota hai. Vision provider alag ho aur VISION_MODEL blank ho to naye provider ka default model use hota hai. **OCR_CLEANUP_PROVIDER blank** ho to extraction provider inherit hota hai; OCR_CLEANUP_MODEL blank ho to us provider ka default model use hota hai.

Ek provider ki **ek hi API key** sab roles mein share hoti hai: OPENAI_API_KEY, ANTHROPIC_API_KEY, GOOGLE_API_KEY. Ollama local service hai aur API key nahi leta. Model name/provider badalne ke liye code edit ki zarurat nahi: project root ki .env file mein selectors set karke worker restart karein. Example mixed setup:

    LLM_PROVIDER=anthropic
    EXTRACTION_MODEL=
    VISION_PROVIDER=google
    VISION_MODEL=
    ENABLE_VISION_FALLBACK=true
    OCR_CLEANUP_PROVIDER=openai
    OCR_CLEANUP_MODEL=
    ENABLE_OCR_CLEANUP=true

Is example ke liye ANTHROPIC_API_KEY, GOOGLE_API_KEY aur OPENAI_API_KEY mein valid keys honi chahiye. Khali model name ka matlab code default hai; kisi role ka exact model chahiye to uske MODEL variable mein naam likh dein. Vision role mein aisa model select karein jo image input handle kare.

    docker compose up -d --force-recreate worker

Abhi jo job report hua, us waqt extraction provider Anthropic tha; vision usi provider/model par configured tha, OCR cleanup off tha. Ollama user ke kehne par abhi stopped hai.
